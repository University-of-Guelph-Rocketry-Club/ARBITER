# Contributing

ARBITER is a club project, so keep changes understandable and help each other learn.

## Basic Workflow

- Do not push directly to `main`.
- Make every change on a branch.
- Bring changes into `main` through a pull request.
- Ask at least one other contributor to review meaningful changes.
- Keep pull requests focused on one topic.
- Once implementation begins, add tests for changes in behaviour.
- Update documentation whenever physical models, assumptions, or requirements change.

Use branch prefixes such as:

```text
feature/
fix/
docs/
test/
refactor/
research/
```

Examples:

```text
feature/atmosphere-model
research/weather-source-comparison
docs/flight-validation
fix/wind-interpolation
```

Pull requests should explain what changed, why it is needed, how it was tested, known limitations, and any related issue.

## Learning Together

ARBITER is intentionally a learning project. Contributors should not need to understand the entire simulator before making a useful contribution.

**Beginner tasks**

- Documentation
- CSV or JSON parsing
- Simple tests
- Sample datasets
- Configuration handling

**Intermediate tasks**

- Weather interpolation
- Coordinate calculations
- Telemetry comparison
- Visualization
- State handling

**Advanced tasks**

- Numerical integration
- Physical model development
- Parameter estimation
- Monte Carlo simulation
- Uncertainty analysis

These levels are guides, not gates. Pair up, ask questions, and work on something that helps you learn.
